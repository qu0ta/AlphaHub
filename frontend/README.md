# AlphaHub frontend

Desktop-кабинет кредитования малого бизнеса: React 19 + TypeScript + Vite + React Router.
Все 23 экрана из Figma («02 Финальный дизайн») свёрстаны в едином стиле UI-kit.

## Запуск

```powershell
Set-Location frontend
pnpm install   # или npm install
pnpm dev       # http://localhost:5173
```

Проверка: `pnpm typecheck` и `pnpm build`.

## Демо-режим (по умолчанию)

Без бэкенда все данные живут в браузере (localStorage). Клиент и сотрудник банка
в одном браузере видят одни и те же заявки — решение банка сразу приходит клиенту.

| Кто | Почта | Пароль |
|---|---|---|
| Клиент (ООО «Север», есть заявка и черновик) | `client@demo.ru` | любой непустой |
| Сотрудник банка | `bank@demo.ru` | любой непустой |
| Новый клиент | регистрация на `/register` | от 8 символов |

Сбросить демо-данные перед показом: открыть `/demo-reset`.

### Сценарий показа

1. Регистрация → заполнение компании по ИНН `6671123450` (ООО «Север»).
2. «Кредитные продукты» → «Выбрать» → мастер заявки из 4 шагов (черновик сохраняется сам).
3. Шаг 3: загрузить любой PDF до 10 МБ → показатели извлекаются за ~3 с, любую ячейку можно исправить.
4. Отправить → статус меняется сам: проверка → финансовая оценка → решение.
   - платёж по текущим кредитам **120 000 ₽** → балл ~60 → заявка уходит **сотруднику банка**;
   - платёж **0 ₽** → балл > 75 → банк **сразу присылает предложение**.
5. Войти как `bank@demo.ru` → очередь → заявка → «Перейти к решению» →
   комментарий + действие (одобрить с условиями / отказать / запросить данные).
6. Клиент: предложение → отклонить с причиной «Высокая ставка» → банк улучшает ставку →
   принять → подписание → «Деньги выданы» → график платежей.

Полезные ИНН для показа состояний поиска:

| ИНН | Что покажет |
|---|---|
| `6671123450` | ООО «Север» найдено |
| `7805123400`, `7722446686`, `667998811274` | другие компании из реестра |
| `7707083893` | компания моложе 6 месяцев — заявку подать нельзя |
| `7736050003` | реестр временно недоступен |
| `1234567890` | ИНН не прошёл контрольную сумму |
| любой другой корректный | компания не найдена |

Файл PDF с «ошибка» или «error» в имени имитирует ошибку распознавания (ручной ввод).

## Настоящий бэкенд

Создайте `frontend/.env.local`:

```dotenv
VITE_API_MODE=api
VITE_API_BASE_URL=
```

Go-бэкенд на `http://localhost:8080`, Vite проксирует `/api`.
Сейчас через API идут авторизация и продукты; компания, заявки, документы,
предложения и кабинет банка — пока мок. Заменяются в одном файле `src/api/client.ts`.

## Структура

```
src/
  api/          client.ts — единая точка доступа к данным; http.ts — fetch к Go;
                mock/ — демо-бэкенд в браузере (seed, db, server)
  components/   ui/ — элементы UI-kit (кнопка, поле, список, бейдж, модалка…)
                layout/ — каркас: боковое меню, верхняя панель, страница
  hooks/        useResource — загрузка данных; usePolling — автообновление статусов
  lib/          format — деньги, сроки, даты; validation — ИНН, пароль; labels — подписи
  pages/        auth/, client/ (+ wizard/), bank/
  state/        auth.tsx — сессия (Context), products.ts
  styles/       tokens.css — цвета/радиусы из UI-kit; base, components, layout, pages
```
