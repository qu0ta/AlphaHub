# AlphaHub: контракт Go ↔ DS

Зафиксирован 22.10.2026 по согласованному сообщению команды DS.
Изменения полей, типов, единиц и статусов согласуются обеими командами.
Машиночитаемое описание: [openapi.json](openapi.json).
Это межсервисный API FastAPI, а не уже реализованные публичные ручки Go.
Адрес сервиса задаётся DS_BASE_URL. Обратные HTTP-запросы из DS в Go не нужны.

## POST /api/v1/financials/extract

Вход: multipart/form-data с одним обязательным полем file, содержащим PDF.
Ограничение содержимого файла — 10 МиБ (10 485 760 байт), без multipart-обёртки.
Успех: HTTP 200, Content-Type: application/json.

FinancialExtractionResponse:

| Поле | Тип | Обязательно |
| --- | --- | --- |
| inn | string | Да |
| financials | MonthlyFinancials[6] | Да |
| declared_monthly_debt_payment_kopecks | int64, >= 0 | Да |

MonthlyFinancials:

| Поле | Тип | Описание |
| --- | --- | --- |
| period_month | string, YYYY-MM | Отчётный месяц |
| revenue_kopecks | int64, >= 0 | Выручка |
| operating_inflow_kopecks | int64, >= 0 | Поступления от основной деятельности |
| operating_outflow_kopecks | int64, >= 0 | Операционные выплаты без налогов и кредитных платежей |
| tax_outflow_kopecks | int64, >= 0 | Налоговые выплаты |

Все поля обязательны, null не допускается. Деньги — целые копейки без дробей и строк.
financials содержит 6 разных календарных месяцев. Порядок не используется для идентификации:
месяц определяется period_month. Требование непрерывности и точный отчётный диапазон
сообщением DS не заданы и дополнительно клиентом не навязываются.
Отсутствующее денежное значение не подменяется нулём.

## POST /api/v1/scoring/evaluate

Вход: application/json, ScoringInput. Все поля обязательны:

| Поле | Тип |
| --- | --- |
| inn | string |
| amount_kopecks | int64, > 0 |
| term_months | int, > 0 |
| financials | MonthlyFinancials[6] |
| declared_monthly_debt_payment_kopecks | int64, >= 0 |

Успех: HTTP 200, application/json, ScoringResponse:

~~~json
{
  "score": 65,
  "explanation": {
    "positive_factors": ["Стабильная выручка", "Положительный денежный поток"],
    "negative_factors": ["Высокая долговая нагрузка"]
  },
  "model_version": "rules-v1"
}
~~~

score — обязательное целое число 0..100 включительно; 0 является валидным значением.
explanation — обязательный объект. Оба массива обязательны и содержат только строки.
Пустые массивы разрешены, null и объекты вместо строк запрещены.
model_version — обязательная непустая строка.
Поле risk_factors в согласованном контракте не используется.
Неизвестные дополнительные поля Go-клиент игнорирует; обязательные поля проверяет.

## Ошибки FastAPI → Go

Сохраняется уже реализованная обработка DSError, новой системы ошибок не вводится.

| HTTP | Значение |
| --- | --- |
| 400 | Некорректный PDF или невозможность извлечь данные |
| 413 | PDF превышает 10 МиБ |
| 422 | JSON не соответствует ScoringInput / ошибка его валидации |
| 500 | Внутренняя ошибка DS |

Во всех этих ответах Content-Type: application/json, структура:

~~~json
{
  "error": {
    "code": "INVALID_PDF",
    "message": "Не удалось извлечь финансовые данные"
  }
}
~~~

code и message — обязательные непустые строки. INVALID_PDF — пример, закрытый перечень
машинных кодов ещё не задан. Клиент сохраняет фактически полученные code/message/status.
Стандартный FastAPI-ответ {"detail": [...]} не соответствует этому формату:
ошибки валидации и внутренние ошибки FastAPI должны быть приведены к общей обёртке.
Для malformed error-body клиент уже использует локальный code INVALID_ERROR_RESPONSE.

Сетевая ошибка/таймаут — ошибка вызова на стороне Go, не HTTP 500, полученный от DS.
Текущий таймаут клиента — 30 секунд; лимит ответа — 2 МиБ. Повторных POST автоматически нет.
Локальная проверка слишком большого PDF возвращает ErrPDFTooLarge до HTTP-запроса.
Авторизация между сервисами отдельно не согласована; сейчас клиент не отправляет credentials.
Публичные ошибки Go для фронта — отдельный контракт; существующие Go-обработчики ещё используют текст.

## Ответственность и порядок

1. Go получает PDF, хранит документ и вызывает extract.
2. DS синхронно возвращает результат извлечения; Go сохраняет его как неподтверждённые данные.
3. Фронт отображает данные; клиент исправляет их и подтверждает.
4. После подтверждения и подачи заявки Go проверяет стоп-факторы.
5. При отсутствии стоп-факторов Go собирает ScoringInput из текущей версии сохранённых данных.
6. DS возвращает формульный скоринг. Go применяет банковские правила и меняет статус транзакционно.

| Score | Действие Go |
| --- | --- |
| 0–39 | Отказ |
| 40–69 | Ручная проверка |
| 70–100 | Проверка лимитов; возможно одобрение |

Высокий score сам по себе не означает одобрение. Стоп-факторы не заменяются скорингом.
DS отвечает за синтетические финансы, тестовые PDF, извлечение, валидацию и расчёт.

## Соответствие текущей БД и оставшаяся интеграция

- На проводе period_month='2026-10'; в DATE сохраняется '2026-10-01'. При чтении обратно — YYYY-MM.
- ScoringInput.amount_kopecks берётся из applications.requested_amount_kopecks.
- ScoringInput.term_months берётся из applications.requested_term_months.
- explanation сохраняется в scoring_results.explanation, model_version — в одноимённое поле.
- features_snapshot формирует Go из фактически отправленного ScoringInput; DS его не возвращает.
- risk_band обязателен в текущей таблице scoring_results, но отсутствует в DS-ответе:
  способ его формирования нужно определить на стороне Go без изменения этого DS-контракта.
- Отдельного столбца для общего declared_monthly_debt_payment_kopecks сейчас нет.
  Нужно выбрать место хранения; это не автоматически исторический платёж каждого месяца.
- financial_records.operating_expenses_kopecks и existing_debt_payment_kopecks остаются
  обязательными, но DS их не возвращает. Их источник/изменение схемы ещё нужно согласовать.
  Нельзя молча приравнивать их к operating_outflow или declared monthly debt.
- HTTP-обработчики Go, хранение/исправление/подтверждение финансов и применение решений
  этим контрактом и DTO не реализуются. DS-клиент пока не включён в рабочий процесс заявки.

Проверка DTO и валидаторов выполняется локальными Go-тестами без вызова DS.
Совместимость с работающим Python-сервисом ещё требует совместной интеграционной проверки.
