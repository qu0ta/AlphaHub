# Ограничения и QA

## Дефекты, влияющие на фронт

### Login игнорирует ошибку JSON

Handler.Login получает err от decodeJSON, но не проверяет.
Неизвестные поля, неверные типы, повреждённый JSON и превышение лимита
не имеют гарантированного единого ответа 400.
Если credentials уже частично декодированы, обработка может продолжиться до выдачи токена.
Если поля пусты — обычно 400 Email and password are required.
Это дефект backend, не поддержка произвольного формата.

### decodeJSON сам пишет ошибку

При втором JSON-значении/мусоре после объекта пишет 400 Invalid request body.
Register затем дописывает Invalid register request: тело может содержать обе строки.
Login способен продолжить обработку после уже отправленного 400.
Не сопоставляйте обязательно весь текст; отправляйте ровно один корректный объект.

### Login маскирует сбой БД

Service.Login возвращает одинаковый ErrInvalidCredentials для ошибки FindByEmail
и отсутствующего пользователя. Ответ — 401 Invalid email or password; различить случаи фронтом нельзя.

### Длины полей

name/email ограничены VARCHAR(255) в БД, но не сервисом.
Превышение может дать 500. Клиентская проверка полезна, но также нужна серверная.

## Не реализовано

CORS/preflight, refresh/logout/revoke, rate limiting, подтверждение email,
восстановление пароля, автоматические миграции и настройка HTTPS в приложении.
Production origin и reverse proxy кодом не определены.
Не считайте эти механизмы доступными при реализации UI.

## Ручной чек-лист

Это предлагаемые сценарии, не отчёт о проведённых runtime-тестах.
Используйте отдельную локальную БД с применённой миграцией.

| Сценарий | Ожидание |
| --- | --- |
| Новая валидная регистрация | 201, CLIENT, без токена/password_hash |
| Пробелы по краям имени/email | Обрезаны, email lowercase |
| Пустое имя | 400 name is required |
| Невалидный email | 400 invalid email |
| Пароль 7/73 ASCII-байта | 400 password must contain 8-72 bytes |
| Пароль 8/72 ASCII-байта | Регистрация проходит при остальных валидных полях |
| Кириллица/emoji в пароле | Длина считается по UTF-8 байтам |
| Повтор email в другом регистре | 409 Email already registered |
| role или нестроковое поле в register | 400 Invalid register request |
| Валидный login | 200, access_token и Bearer |
| Неверный пароль/нет пользователя | 401 Invalid email or password |
| Пустые credentials | 400 Email and password are required |
| me с действительным JWT | 200, актуальный профиль |
| me без заголовка/с Basic | 401 Bearer token is required |
| me с повреждённым/истёкшим JWT | 401 Invalid or expired token |
| Пользователь токена удалён из тестовой БД | 401 User not found |
| Выход из UI | Очищены токен, профиль, приватный кэш |
| me завершился после выхода | Сессия не восстанавливается |
| me = 500 или сеть | Ошибка доступности с повтором, без ложного вывода о неверном пароле |
| Браузер через proxy | Ответ читается без CORS-блокировки |
| Перезагрузка с токеном только в памяти | anonymous |

Для malformed JSON login и нескольких JSON-значений учитывайте дефекты выше.

## Согласовать при развитии

Единый JSON ошибок и коды; исправление decodeJSON/login; длины name/email;
production origin/CORS/proxy; долговременную сессию/refresh/revoke;
контракты компаний, заявок, изменения профиля и банковских действий.
Это будущие решения, не реализованные эндпоинты.
