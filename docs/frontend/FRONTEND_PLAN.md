# План фронтенда AlphaHub

## Архитектура

- `frontend/src/api` — HTTP-клиенты и преобразование backend DTO.
- `frontend/src/state` — сессия пользователя.
- `frontend/src/data` — временные бизнес-моки.
- `frontend/src/components` — UI и общий layout.
- `frontend/src/pages` — пользовательские сценарии.

## Что подключено к backend

| Сценарий | Готовность |
| --- | --- |
| Регистрация | Контракт подключён |
| Вход | Контракт подключён |
| Текущий пользователь | Контракт подключён |
| Активные продукты | Клиент подготовлен |
| Компания и ИНН | Мок, API отсутствует |
| Заявки | Мок, API отсутствует |
| PDF и финансовые данные | Мок, API отсутствует |
| Статусы и история | Мок, API отсутствует |
| Офферы | Мок, API отсутствует |
| Кабинет банка | Мок, API отсутствует |

## Следующие контракты от backend

1. Компания: поиск по ИНН, создание и чтение профиля.
2. Заявки: черновик, обновление шагов, отправка, список и карточка.
3. Документы: multipart upload, статус обработки, извлечённые показатели.
4. Статус: история, запросы дополнительных данных, повторная отправка.
5. Оффер: чтение, принятие, отклонение с причиной.
6. Банк: очередь, фильтрация, карточка, скоринг и решение.

Для каждого контракта нужны HTTP-метод, путь, DTO, ошибки, роли и пример ответа.

## Порядок продолжения

1. Запустить MVP в mock-режиме и пройти оба пользовательских пути.
2. Запустить backend и проверить auth через `VITE_API_MODE=api`.
3. Подключать новые ручки по одной, сохраняя мок как fallback только для разработки.
4. После стабилизации контрактов добавить runtime-валидацию ответов.
5. Перед демонстрацией зафиксировать seed-данные и сценарий презентации.

## Не входит в MVP

- мобильная и планшетная версии;
- production deployment;
- refresh token и серверный logout;
- настоящее распознавание PDF на фронте;
- сложные анимации;
- полноценная дизайн-система.
