# План работы на 8 часов

## 0:00–0:30 — запуск и обзор

1. Открыть `frontend`.
2. Запустить `pnpm dev`.
3. Войти как клиент и сотрудник банка.
4. Показать структуру `api → state → pages → components`.

Результат: каждый понимает, что уже работает и где менять код.

## 0:30–1:30 — авторизация

1. Запустить Go backend и PostgreSQL.
2. Создать `frontend/.env.local` с `VITE_API_MODE=api`.
3. Проверить регистрацию, login и `me`.
4. Согласовать тестового сотрудника банка.

Результат: настоящая сессия клиента.

## 1:30–3:30 — компания и заявки

Если API готовы, подключить компанию и заявки. Иначе сохранить моки и довести формы.

Распределение:

- фронтенд: формы, API-клиенты, состояния загрузки и ошибок;
- backend: компания, черновик, список, карточка и submit;
- ML: контракт извлечённых финансов и скоринга.

## 3:30–5:00 — документы и статусы

1. Multipart upload PDF.
2. Поллинг состояния обработки или кнопка обновления.
3. Редактирование извлечённых показателей.
4. История статусов и запрос дополнительных данных.

## 5:00–6:30 — оффер и кабинет банка

1. Получение оффера.
2. Принятие и отказ с причиной.
3. Очередь банка и фильтры.
4. Решение сотрудника.

## 6:30–7:30 — интеграционная проверка

Пройти два сценария:

1. Клиент: регистрация → компания → заявка → оффер → принятие.
2. Банк: вход → очередь → карточка → решение.

Фиксировать только блокирующие ошибки.

## 7:30–8:00 — подготовка демо

1. Зафиксировать seed-данные.
2. Очистить консоль и критичные ошибки.
3. Проверить production build.
4. Записать порядок демонстрации и запасной mock-сценарий.

## Стоп-условия

- Не делать адаптив.
- Не менять дизайн без блокирующей причины.
- Не добавлять Redux, сложную дизайн-систему или анимации.
- Не ждать недостающий API: использовать контрактный мок.
- Не деплоить до завершения локального демо.
